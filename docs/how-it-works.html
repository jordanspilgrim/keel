The system, layer by layer

The agent loop

One retention conversation runs through this pipeline, resolving to saved / lost / escalated.

  1. AI disclosure
    The first turn tells the customer they’re talking to an AI. Enforced as an input-side guardrail so it can never be skipped (EU AI Act Art. 50).
  2. Input guardrails
    Every customer message is screened: a defined set of sensitive patterns (card / SSN / email / DOB / phone + heuristic names & street addresses) redacted before storage, known jailbreak patterns caught (100% on the 14 seeded probes — common paraphrases can still evade regex; the deterministic policy layer is the real backstop), off-topic requests bounded.
  3. Reason + call tools
    The model (flagship) grounds itself with get_customer / get_subscription / get_usage, then proposes a retention offer. It can only ever see the authenticated customer’s own records.
  4. Policy disposes
    Deterministic authorization caps or rejects the proposal — discount depth, margin floor, save-offer cooldown — and routes consequential actions to a human.
  5. Output guardrails
    The final turn is a structured intent, not prose: the model picks an acknowledgement from a fixed set, an offer as kind+terms, and account facts by reference — and the server renders every sentence from data it validated against the offer ledger and tool results. The model never authors a customer-facing sentence, so there is no free-form channel for an invented account fact, capability, refund, or cancellation. The customer only ever reads server-rendered text.
  6. Structured disposition
    A JSON-schema disposition (intent, churn_reason, offer_made, offer_accepted, outcome, confidence) is produced and reconciled with the loop’s ground-truth outcome.
A conversation is only counted saved when the customer accepts a real retention offer. Someone agreeing to cancel is a churn, not a save — a distinction that keeps the downstream analytics honest.

Guardrails — defense in depth

Guardrails aren’t a prompt instruction (“please don’t…”). They’re enforced layers: known jailbreak patterns are blocked before the model (100% on the 14 seeded probes — regex, so paraphrases can evade it; the deterministic policy layer is the real backstop), actions are deterministically authorized, and the customer-facing reply must pass a structured contract validated against the offer ledger and tool facts — a reply whose prose overstates the declared offer or invents an account fact is regenerated once and, failing that, held at the authorized ceiling or handed to a human. Every trip is written to guardrail_events.

ToneA moderation pass for harmful or off-brand content; a hard tone failure escalates to a human.
The elegant part: the guardrail layer, the eval layer, and the analytics layer are the same observability spine viewed three ways — enforce, score, aggregate.

Compliance, built in

The retention agent is a limited-risk system under the EU AI Act (transparency only). It would become high-risk only if pointed at credit / insurance / health eligibility — the POC deliberately stays on the limited-risk side.

The economics that shape the design

The unit-economics model surfaces one finding that reframes everything: ~97% of blended cost-to-serve is human escalation; the entire AI stack — agent, grading every conversation, guardrails — is about 3¢ per conversation.

Two consequences are baked into the design: the optimization lever is containment (safely reducing escalation), not model choice or token-shaving; and you grade 100% of conversations because evaluation is nearly free. Sampling to “save money” saves nothing and costs you signal. Explore the model →

All six phases built and verified end-to-end — agent, guardrails, evals, analytics, and the closed loop (acting on one analytics signal, the treated price-sensitive segment's save-rate lift had a pre-registered median of +15.0pp, range [+6.7, +21.7]pp across 5 runs — all positive, at a treated cohort of n=60; the committed median-lift run (run-20260725T071548) moved it 10% → 25%. Three pre-registered median-of-5 estimates have now been run and all are retained: +11.7pp, +23.3pp, and this one. The middle was inflated by a real defect — the agent loop escalated without presenting an offer policy had already authorized, and the baseline arm burned extra hops retrying because its policy rejects discounts, so the hop budget bound the arms asymmetrically (fixed in R12). But the first two were ~12pp apart on materially the same measurement path, so the drop must not be read as cleanly “the confound was worth 8pp”: the estimator's own spread is the same order as the effect being corrected. The honest read is a consistently positive lift in roughly the +7–25pp band across three independent estimates, not a point estimate). A single run is high-variance because both arms are LLM-simulated, so the headline is a pre-registered median-of-5 (fixed seed, every run counted, median not max), not any one lucky draw.
